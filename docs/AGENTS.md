# Instructions for documentation

1. Update README, feature specs, contracts, ADR, runbooks and CHANGELOG only when
   applicable to the behavior changed; link to one source of truth.
2. Clearly separate implemented, in progress, planned and non-scope behavior.
3. Verify commands, paths, links and technical assertions against implementation.
4. Do not expose private motivation, local AI history, secrets, PII or real data.
5. Explain decisions, alternatives, operational failure modes and rollback without
   duplicating source code line by line.
