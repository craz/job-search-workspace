# Локальная история общения с AI-инструментами

Проект предоставляет общий механизм локального хранения исходных session exports
Codex, Cursor и других AI-инструментов. Механизм и правила находятся в Git;
пользовательские сессии всегда остаются локальными в `.local/`.

## Быстрый старт

```bash
scripts/init-ai-history.sh
```

Команда идемпотентна: создаёт отсутствующие файлы, но не перезаписывает
существующую историю.

После инициализации доступны:

- `.local/sessions/<tool>/` — оригинальные session exports или ссылки на них;
- `.local/AI_HISTORY.md` — краткая инженерная история решений и выполненной работы.
- `.local/derived/` — необязательные представления, построенные из raw-сессий.

Для последующей синхронизации Codex-сессий, относящихся к текущему repository
working directory, используется:

```bash
make ai-history-sync
```

Команда находит platform exports по записанному в них `cwd`, создаёт ссылки в
`.local/sessions/codex/` и атомарно пересобирает
`.local/derived/AI_CHAT_RAW.md`. Её безопасно повторять, в том числе во время
активной сессии: неполная последняя JSONL-строка игнорируется. Сессии из других
рабочих каталогов не подключаются.

Каталог `.local/` находится в `.gitignore`. Его содержимое нельзя добавлять в
Git даже принудительно без отдельного осознанного решения пользователя.

## Canonical raw

Canonical raw — оригинальный файл, созданный AI-платформой или экспортированный
пользователем. Он сохраняется без преобразования в Markdown, нормализации и
пересказа:

- environment context;
- видимые сообщения User/Assistant;
- commentary и phase;
- tool calls и их аргументы;
- tool outputs, ошибки и approvals;
- timestamps и платформенные метаданные.

Рекомендуемая структура:

```text
.local/
├── sessions/
│   ├── codex/
│   ├── cursor/
│   └── other/
├── derived/
├── AI_HISTORY.md
└── PROJECT_CONTEXT.md
```

Session export можно скопировать или подключить символической ссылкой. Ссылка
предпочтительна, если платформа уже надёжно хранит оригинал локально; копия нужна
для переноса или резервирования истории.

Символическая ссылка делает canonical export доступным внутри проекта, но сам
оригинал остаётся во владении платформы. Для переносимой резервной копии нужна
отдельная явно запрошенная операция копирования.

Не пытаться дополнять platform export скрытыми данными. AI-инструмент не должен
извлекать или раскрывать:

- скрытые рассуждения модели;
- системные и developer-инструкции, которые платформа не предоставляет как
  пользовательский transcript;
- токены, cookies, пароли и browser profile;
- персональные данные третьих лиц;
- приватную переписку, не предназначенную для журнала.

Backfill выполняется только из фактического session transcript или
пользовательского экспорта, а не по памяти AI-инструмента.

## Derived representations

Markdown, HTML, поисковый индекс и очищенный event stream являются производными
артефактами. Они сохраняются в `.local/derived/`, могут быть пересозданы из raw и
никогда не заменяют оригинальный platform export.

## Summary-журнал

После содержательного завершённого шага добавляется запись:

```markdown
## YYYY-MM-DD HH:MM — <инструмент>

- Запрос: краткое содержание задачи.
- Решения: что выбрано и почему.
- Изменения: файлы и внешние действия.
- Проверки: команды и результаты.
- Git: commit hash или причина отсутствия commit.
- Осталось: незавершённые вопросы и следующий шаг.
```

Summary не дублирует полный transcript. Он помогает продолжить работу другим
AI-инструментом или в новой сессии.

## Приоритет источников

История является вспомогательной памятью, а не source of truth. При расхождении
приоритет имеют:

1. Код и автоматические тесты.
2. Публичные контракты и миграции.
3. Принятые ADR и feature specs.
4. Git-история.
5. AI summary и platform session exports.
